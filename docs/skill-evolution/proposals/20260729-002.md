# Proposal: Create codebase-memory-mcp Skill

## 1. What is wrong today

There is no Hermes skill that documents the `codebase-memory-mcp` CLI workflow for listing, indexing, and batch-indexing projects. When a user needs to set up codebase-memory indexing — a recurring task as new projects are added — every agent must discover the CLI commands from scratch: running `--help`, guessing the JSON argument format, debugging `repo_path is required` errors, and assembling a shell script for cron. The session that triggered this proposal spent 10+ tool calls just to figure out the CLI interface, plus additional calls to write and test the cron job shell script. A skill would save all of that on the next occurrence.

## 2. Evidence

Session `20260727_074944_be429d` ("Crear cron job codebase memory sin error", TUI, 35 messages, 1 user message) shows the full discovery cost:

1. **First attempt: find the tool** — searched `tool_search` for "codebase memory mcp index project" → no relevant tools found (only Playwright MCP tools)
2. **Discover the binary** — `which codebase-memory-mcp` found it at `~/.local/bin/codebase-memory-mcp`
3. **Learn the CLI** — ran `codebase-memory-mcp --help` to discover the `cli` subcommand
4. **Learn subcommand syntax** — tried `codebase-memory-mcp cli --help` → error `unknown tool: --help` (the `cli` subcommand doesn't support `--help`)
5. **List projects** — successfully ran `codebase-memory-mcp cli list_projects '{}'` to see already-indexed projects
6. **Try indexing** — `codebase-memory-mcp cli index_project '{}'` → error "repo_path is required"
7. **Discover path format** — eventually figured out correct invocation: `codebase-memory-mcp cli index_project '{"path": "/repo/path"}'`
8. **Index 5 projects individually** — each project required one tool call
9. **Write a shell script** — composed `~/.hermes/scripts/codebase-memory-daily-index.sh` to batch-index all 10 projects
10. **Create the cron job** — had to search for delivery delivery channel config, then created via `hermes cron create`

Each of these steps represents knowledge that a skill would encode directly, cutting the setup from ~15 tool calls to ~3.

The error the user originally reported — `mcp__playwright__browser_snapshot [error: "project not found or not indexed"]` — was caused by this exact knowledge gap: the agent didn't know how to index a missing project via the CLI.

### Proposed body sections

**1. CLI Reference**

| Command | Purpose | Example |
|---------|---------|---------|
| `codebase-memory-mcp cli list_projects '{}'` | List all indexed projects with node/edge counts | |
| `codebase-memory-mcp cli index_project '{"path": "/abs/path"}'` | Index a single project by absolute path | |
| `codebase-memory-mcp cli detect_changes '{}'` | Check for changes in all indexed projects | |

**2. Common Workflows**

- **Check if a project is indexed:** `codebase-memory-mcp cli list_projects '{}'` and grep for the project name
- **Index a new project:** `codebase-memory-mcp cli index_project '{"path": "/Users/.../repo"}'` — the project name is auto-derived from the path
- **Batch-index multiple projects:** use the shell script template below

**3. Shell Script for Daily Cron Indexing**

```bash
#!/bin/bash
# Daily codebase-memory index — designed as a no_agent cron job
# Place at: ~/.hermes/scripts/codebase-memory-daily-index.sh

REPOS=(
  "/Users/carloalva/Projects/agent-skills"
  "/Users/carloalva/Projects/ai-memory-stack"
  "/Users/carloalva/Projects/money-admin"
  "/Users/carloalva/Projects/cv-generator"
  "/Users/carloalva/Projects/surf-buddy"
  "/Users/carloalva/Projects/hermes-skill-evolution"
  "/Users/carloalva/Projects/compound-engineering-plugin"
  "/Users/carloalva/Projects/Carlo1911.github.io"
  "/Users/carloalva/Projects/comidas-tracker"
  "/Users/carloalva/Projects/Xperiments"
)

for repo in "${REPOS[@]}"; do
  echo "[INDEX] $(basename $repo)..."
  codebase-memory-mcp cli index_project "{\"path\": \"$repo\"}"
done
```

**4. Cron Job Setup**

```bash
# From the agent:
1. Save the script to ~/.hermes/scripts/codebase-memory-daily-index.sh
2. Make executable: chmod +x ~/.hermes/scripts/codebase-memory-daily-index.sh
3. Create cron job:
   cronjob(action='create', name='codebase-memory-daily-index',
           schedule='0 3 * * *', no_agent=True,
           deliver='all',
           script='codebase-memory-daily-index.sh',
           workdir='~/.hermes')
```

Prefer `no_agent=True` for batch indexing — it runs without LLM overhead. Set `deliver` to `all` to get a summary on Telegram, or `none` for silent operation.

**5. Troubleshooting**

| Error | Likely Cause | Fix |
|-------|-------------|-----|
| `repo_path is required` | Empty JSON or wrong key name | Use `{"path": "/abs/path"}` not `{"repo_path": "..."}` or `{"project": "..."}` |
| `project not found or not indexed` | Project never indexed, or index deleted | Index it with `index_project` first; then search works |
| `unknown tool: --help` | CLI subcommand has no `--help` flag | Omit `--help`; use the top-level `codebase-memory-mcp --help` for command list |
| Error persists after indexing | Stale MCP connection | Restart the MCP server: `/reload-mcp` in chat, or restart the gateway |

**6. Pitfalls**

- **CLI subcommand does NOT support `--help`** — running `codebase-memory-mcp cli --help` errors with `unknown tool: --help`. Use the top-level `--help` for command discovery.
- **Path must be absolute** — relative paths cause silent failures or errors.
- **Project names are auto-derived** from the directory basename with a `/Users/.../` prefix normalized to dots. Not manually controllable.
- **Re-indexing is safe** — running `index_project` on an already-indexed project updates it without errors.
- **`list_projects` returns all projects** — large installations may have many entries. Pipe through `jq` or grep for specific projects.

## 4. What improves, and how you would know

**Behavioral change:** When a user says "set up codebase-memory indexing for my projects" or hits a "project not found" error, the agent will:
1. Load the `codebase-memory-mcp` skill
2. Know the exact CLI invocation for listing, indexing, and batch operations
3. Use the shell script template instead of composing one from scratch
4. Create a proper cron job with `no_agent=True` and correct delivery config

**Verification check:** After creating the skill, ask the agent: "Index my project X in codebase-memory." The agent should use `codebase-memory-mcp cli index_project '{"path": "/abs/path/of/project"}'` on the first try, without any `--help` exploration or debugging the JSON format.

## 5. Trade-offs and risks

- **CLI interface may change:** `codebase-memory-mcp` is a third-party tool. Future versions could change the subcommand syntax, argument format, or binary path. Mitigation: version-pin the commands in the skill and add a "Check current version" note (`codebase-memory-mcp --version`).
- **Shell script is user-specific:** The proposed script hard-codes Carlo's project paths. The skill should use placeholders or a generic template that users customize. Mitigation: use `${REPOS[...]}` as a clear customization point in the template.
- **Only 1 session of evidence:** This gap is well-documented in the session (10+ discovery tool calls), but a second session hitting the same gap would increase confidence. Single-session evidence is still actionable — the discovery cost is real and reusable.
- **Binary location varies:** `which codebase-memory-mcp` may return different paths depending on install method (npm global vs pipx vs brew). Mitigation: document that users should verify with `which` and adjust the script's PATH accordingly.
